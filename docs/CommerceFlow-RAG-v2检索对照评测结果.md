# CommerceFlow RAG v2 真实检索对照与本地灰度结果

2026-10-23，在项目配置的真实 MySQL、Milvus 和 BigModel Embedding/Rerank API 上完成。

实际迁移完成：6 份文档、6 个版本、52 个块已发布到独立 v2 索引；旧表和旧索引各 52 条保留。6 份源文件指纹及旧表全部字段与迁移前快照一致，v2 的 52 条索引来源、版本和正文与 MySQL 一致。

## 对照口径

- 同一份 300 题数据集中的 A/B/C/E 四桶各 60 题，共 240 道可答题；每个索引四种策略各 240 次检索，共 1,920 次。
- 使用 `--skip-gen`：本轮完成检索及机械证据覆盖度；未执行生成、LLM 裁判或 D 桶 60 道库外题拒答评估。
- 新旧串行运行，检索并发 2，单题超时 90 秒；完整日志记录这些参数。原 JSON 的 `meta.concurrency=5` 指生成并发，生成本轮未运行；脚本后续报告已增加独立检索并发与超时字段。
- Recall@5 按章节证据匹配；跨文档题按所需证据组给部分分。MRR 按 Top-10 中各所需证据倒数名次取平均。机械覆盖度为标准要点在 Top-10 证据中的去空白子串匹配，不等于答案正确率。
- P95 是取得检索并发槽之后整条检索链的耗时，包含必要的查询拆分、向量化和重排，不是仅 Milvus 查询耗时，也不是生产吞吐压测。

## 实测总体指标

| 策略 | 索引 | Recall@5 | MRR | 机械证据覆盖率 | P95（秒） | 失败率 |
|---|---|---:|---:|---:|---:|---:|
| vector | legacy | 0.928 | 0.761 | 0.978 | 0.637 | 0/240 |
| vector | v2 | 0.919 | 0.769 | 0.981 | 0.776 | 0/240 |
| bm25 | legacy | 0.913 | 0.783 | 0.962 | 0.038 | 0/240 |
| bm25 | v2 | 0.913 | 0.783 | 0.962 | 0.045 | 0/240 |
| hybrid | legacy | 0.938 | 0.814 | 0.991 | 0.667 | 0/240 |
| hybrid | v2 | 0.934 | 0.817 | 0.985 | 0.701 | 0/240 |
| hybrid_rerank | legacy | 0.974 | 0.698 | 0.997 | 32.310 | 0/240 |
| hybrid_rerank | v2 | 0.976 | 0.687 | 0.998 | 28.673 | 0/240 |

v2 重排 Recall 提高 0.2 个百分点，机械覆盖率提高 0.1 个百分点，MRR 下降 0.011；纯向量 Recall 下降 0.9 个百分点，混合 Recall 下降 0.4 个百分点。BM25 指标持平。此次重排 P95 从 32.31 秒降至 28.67 秒，但上游服务与串行运行时段会影响延迟，不能据单次对照归因于模型改造。

当前不能宣称四策略全面提升，也未约定可接受的指标退化门槛。主 `.env` 继续使用 legacy，独立本地实例使用 v2；不进行全量默认切换。
